# Repository workflow

Use for an explicitly requested setup or a material missing delivery convention.
Reuse existing instructions instead of creating a second policy source.

- Repository and intended delivery endpoint.
- Source control and work tracker, or local work documents.
- Local workspace rules and required verification references.
- Permitted edits, commits, remote writes, integration, and deployment.
- Human-review checkpoints, reviewer, and review artifact/channel.
- Completion endpoint and any verified enforcement controls.

Record only agreed rules. A task can narrow its endpoint; expanded authority must
come from an authorized instruction within the client's policy. Keep commits and
pushes separate. A server-side check-in or shelveset is a remote write, not a local
commit. A no-PR workflow returns the appropriate local changes or authorized commit
for human review. Give the base revision, complete change artifact, and verification
evidence. Preserve existing authorization within scope; material changes to a
human-reviewed artifact return to the required review checkpoint.
