# Shared decision maps

Use the existing tracker conventions or local Markdown equivalent. Read the map's
destination, notes, decision index, unresolved areas, and exclusions. Honor named
child work; otherwise select an open, unblocked, unclaimed decision. Claim it using
the repository's convention and confirm ownership before starting shared work.

Investigate facts, prototype behavior, or ask the user about product choices as
needed. Human decisions require the human's answer. Record the resolution on its
decision ticket, link evidence, and close it only when resolved. Update the map's
decision index with a brief summary and a descriptive link to that canonical answer.

Reassess dependencies and unresolved areas after each resolution. Create newly
specifiable child decisions, then wire their dependencies using native relationships
where supported. Remove graduated questions from the unresolved area; keep exclusions
separate. Explain and reconcile invalidated decisions or out-of-scope tickets without
silently discarding history. Preserve other workers' ownership and edits.

Creating a requested map uses the same structure: destination, notes, decisions,
unresolved areas, exclusions, and linked child questions. Keep each answer in one
place. A map is complete when the destination has no blocking unresolved decisions;
ticket closure alone is insufficient. Carry results into any requested specification.
Continue through authorized unblocked work without a one-ticket session limit.
Tracker writes follow the task's authority; draft proposed updates locally when the
task is read-only. Planning does not implicitly authorize production implementation.
